What to expect

Middle-click tries to open the destination in a background tab. The same rules apply across permitted websites. Purple fist means ON; grey means OFF. Click the toolbar icon to switch the entire addon on or off.

The original page cannot always be kept untouched. Some controls reveal their destination only after their code runs. That code can change the page or send a request before navigation is stopped. A copy can miss temporary panels or unsaved state; websites may also open extra popups or refuse simulated clicks. Firefox-protected pages remain unsupported.

Firefox 147 or newer is required. This testing build keeps local diagnostic tools separate from the public release. Automated checks simulate browser behavior; they do not guarantee every website works.

The copied page now keeps the same matched button ready for at least 1.5 seconds before one automatic press. If the page replaces that button while loading, the wait restarts. Direct links, images and card destinations retain their existing behavior.

Automatic handling, one toolbar toggle

Direct links, clear card/title relationships and displayed images come first. If those do not reveal a destination, the addon checks for a clear address stored on the control's own app component. An unresolved eligible control can then use a background copy. These methods run automatically while the toolbar is ON; there are no separate testing switches, and old saved testing settings are ignored.

The copied page must recreate one matching control before the addon presses it once there. Allow up to 15 seconds. You can switch tabs or view the copy while it prepares. Clicking or typing inside the copy stops automatic replay. Once a click may have reached the copy, it is never automatically repeated on the original.

If a copy is unavailable or definitely fails before any activation, the existing discovery fallback may press the original control to learn its destination. This comes last because it can change the source page.

Open Preferences in Firefox to see the last copy status.

Record a website problem

Recording is manual and local. It does not switch any navigation feature on or off. Choose Record next middle-click, click the troublesome control once, and wait about 10 seconds before copying the updated report.

The report excludes typed form values, page titles, query strings and fragments, but address paths and page relationship IDs can still identify private content. Review it before sharing. Nothing is uploaded automatically. Open a GitHub website report with your browser/addon versions, clicked item and what happened in both tabs.

Open this page through the addon's Preferences in Firefox to record a click.

3.0.0 — Destination-first prototype

October 25, 2026 · Experimental, unreleased

  • Corrected priority: a source-page change is acceptable when needed to discover the destination.
  • Watch, then activate: unknown eligible controls receive one simulated normal click only after the background navigation watcher is ready.
  • Watch outside the page: full-page, SPA address and hash navigation can be detected even if the original page unloads.
  • One owned attempt: repeated notifications do not create another extension tab. Detection expires after eight seconds; overlapping unknown attempts can be rejected.
  • Existing new tabs: a page-created tab/window detected promptly counts as the result instead of opening another copy. Late popups and their focus are not guaranteed.
  • No rollback: the original page is allowed to change. Forms, editable and disabled controls are excluded from automatic activation.
  • Retained: saved toolbar toggle, correct blue/grey fist icons, container/window handling and once-per-version changelog.

Duplicate-and-activate and the live-tab swap are researched designs, not implemented features of this prototype.
